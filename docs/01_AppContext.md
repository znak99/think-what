---

## 앱 개요

| 항목 | 내용 |
|------|------|
| 장르 | 초성 맞추기 드로잉 게임 (캐치마인드 변형) |

## 기능 명세

### 인증/인가

| 기능 | 설명 |
|------|------|
| 회원가입 | 이메일 + 비밀번호(8자+) + 닉네임(4~20자). 이메일/닉네임 중복 불가. 성공 시 바로 게임화면으로 이동 |
| 로그인 | 이메일 + 비밀번호. 성공 시 게임화면으로 이동 |
| 비밀번호 재설정 | 이메일 + 닉네임 일치 확인 → 새 비밀번호 입력 → 로그인화면으로 이동 |
| 로그아웃 | 토큰 삭제 |

> **고지 필수**: 회원가입 화면에 "이메일과 닉네임을 반드시 메모해두세요. 비밀번호 재설정에 사용됩니다." 표시

### 게임 플로우

1. 로그인 → 게임화면 진입 (참가자 수 + 닉네임/랭크 목록 표시)
2. 2명 이상 → 랜덤 출제자 지정 (직전 출제자 제외) → 3초 카운트다운 → **3분 타이머 시작**
3. 출제자: 제시된 초성(ex: `ㅎㅂㄱ`) 확인 후 그림 그리기
4. 참가자: 채팅으로 초성 입력 → 정답 시 다음 출제자 됨
5. 게임 도중 입장한 참가자는 즉시 참여 가능 (현재 캔버스 복구됨)
6. 3분 타이머 종료 → "3초 후 출제자를 변경합니다." 표시 → 캔버스 초기화 + 새 출제자 지정

### 출제자 전용 UI

- 펜 색상 변경: 검(기본) / 빨 / 주 / 노 / 초 / 파 / 남 / 보
- 전체 지우기 버튼
- 현재 초성(정답) 표시

### 채팅

- 일반 채팅 + 정답 판정 통합 (같은 입력창 사용)
- 정답 입력 시 서버 도착 시간 기준 밀리초 단위 선착순 처리

### 출제자 재배정 투표

- 참가자만 투표 가능
- **과반수** 동의 시 재배정
- 투표 재실행 쿨다운: **5분**

## 랭크 시스템

### 포인트 공식

```
정답자 포인트 = (100 + 60 × log₂(n-1)) × time_bonus × streak_bonus

n         = 현재 참가자 수 (출제자 포함), n ≥ 2
출제자    = 포인트 없음

time_bonus:
  0 ~ 60초:    × 1.5
  61 ~ 120초:  × 1.2
  121 ~ 180초: × 1.0

streak_bonus (연속 정답):
  1회:  × 1.0
  2회:  × 1.1
  3회+: × 1.2 (상한)
```

**참가자 수별 기본 포인트 (time/streak 보너스 제외):**

| 참가자 수 | 포인트 |
|----------|--------|
| 2명 | 100점 |
| 5명 | 220점 |
| 10명 | 292점 |
| 30명 | 394점 |
| 100명 | 496점 |

### 랭크 경계값

| 랭크 | 배지 색상 | 누적 포인트 |
|------|----------|------------|
| 1등급 | ⬛ 검은색 | 0 ~ 499 |
| 2등급 | 🟫 갈색 | 500 ~ 1,999 |
| 3등급 | ⬜ 은색 | 2,000 ~ 5,999 |
| 4등급 | 🟨 금색 | 6,000 ~ 14,999 |
| 5등급 | 💚 에메랄드 | 15,000 ~ 39,999 |
| 6등급 | 🌈 무지개 그라디언트 | 40,000+ |

> 평균 ~260점/정답 기준, 무지개까지 약 50~70시간 플레이 예상

## 설계 결정 사항

### WebSocket 이벤트 구조
- 드로잉 이벤트, 채팅, 정답 판정, 투표, 게임 상태를 단일 WS 연결로 처리
- 이벤트 타입으로 구분

### 캔버스 동기화
- **이벤트 기반 스트리밍**: 드로잉 이벤트를 모든 참가자에게 브로드캐스트
- 중간 입장 참가자에게는 현재까지의 이벤트 재생 or 스냅샷 전송

### 연결 끊김/재연결
| 상황 | 처리 |
|------|------|
| 참가자 연결 끊김 | 재접속 시 캔버스 복구 후 즉시 참여 |
| 출제자 연결 끊김 | 게임화면에 "출제자 연결 끊김" 표시 → 새 출제자 자동 지정 |

### 정답 판정
- 서버 도착 시간 기준 밀리초 단위 선착순
- Race condition → 서버 레벨 atomic 처리 (DB 트랜잭션)

### 인증
- JWT: Short-lived Access Token + Refresh Token
- 비밀번호 재설정: 이메일 발송 없이 이메일+닉네임 일치 확인 방식

### 확장성
- MVP: 단일 서버
- 추후: 로드밸런서 + Sticky Session (WebSocket 특성상 필요)

### 초성 데이터
- MVP: 난이도 구분 없음
- 단어 목록은 직접 작성 제공 → DB 시드 데이터 삽입
